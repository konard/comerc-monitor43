# Агент 16: Regulatory requirements

## Персональные данные (152-ФЗ)

### Что нужно

**Федеральный закон № 152-ФЗ** — основной закон РФ о персональных данных, регулирующий обработку, хранение и защиту информации о физических лицах.

#### Основные требования (актуально для 2025-2026):

| Требование | Описание |
|------------|----------|
| **Локализация данных** | Все записи, систематизация, накопление, хранение, уточнение и извлечение персональных данных граждан РФ должны осуществляться с использованием баз данных, находящихся **на территории РФ** |
| **Разделение согласия** | С 1 сентября 2025: согласие на обработку персональных данных должно быть **полностью независимым** от других документов или соглашений (запрет на "комплексные соглашения") |
| **Уведомление Роскомнадзора** | Об изменениях в обработке ПД — до 15-го числа следующего месяца |
| **Уведомление об утечках** | Первичное уведомление в течение 24 часов, полный отчет — в течение 72 часов |

#### Штрафы за нарушение (обновлено в мае 2025):

- **Обычные нарушения**: до 3 млн рублей (~$30,000)
- **Нарушения с чувствительными данными**: до 5 млн рублей (~$50,000)
- **Не локализованное хранение**: 5 млн рублей за первое нарушение; при повторном — возможна блокировка сервиса
- **Уголовная ответственность** (ст. 272.1 УК РФ): до 5 лет лишения свободы за незаконное использование, передачу, сбор или хранение персональных данных

### Для мониторинга

#### Какие данные мы можем собирать?

**Персональные данные (требуют соблюдения 152-ФЗ)**:
- Имя пользователя
- Email
- IP-адрес
- User Agent
- Логи авторизации
- Любые данные, позволяющие идентифицировать пользователя

**Не персональные данные (метрики систем)**:
- CPU, Memory, Disk usage
- Network I/O
- System uptime
- Error rates
- Response times
- Service metrics без привязки к конкретным пользователям

#### Как хранить?

1. **Серверы в РФ**: Обязательно для любых данных граждан РФ
2. **Анонимизация**: Агенты должны анонимизировать данные отправки
3. **Разделение данных**: Хранить метрики отдельно от идентификаторов пользователей
4. **Шифрование**: Обязательно для чувствительных категорий данных

## Локализация ПО

### Реестр российского ПО

Управляется Министерством цифрового развития (Минцифры). Включение в реестр даёт приоритет при госзакупках.

#### Нужно ли включаться?

**Для SaaS мониторинга**:

| Сценарий | Нужно ли включение |
|----------|-------------------|
| B2C клиенты в РФ | Рекомендовано |
| Работа с госсектором | **Обязательно** |
| Работа с крупным бизнесом | Сильно рекомендуется |
| Только международные клиенты | Не требуется |

#### Преимущества включения

- **Приоритет в госзакупках**: Госорганизации обязаны покупать российское ПО при наличии аналогов
- **Маркетинг**: Статус отечественного ПО повышает доверие
- **Налоговые льготы**: Ноль НДС для IT-компаний (при выполнении условий)
- **Гранты и поддержка**: Доступ к госпрограммам поддержки

#### Процесс включения (2025)

1. Подготовить документацию, подтверждающую российское происхождение ПО
2. Подать заявку через портал Минцифры
3. Пройти экспертизу (до 30 рабочих дней)
4. **С 2025**: Обязательно подтвердить совместимость минимум с **двумя российскими ОС** из реестра (для ПО разных категорий)

#### Требования к совместимости (поэтапно):

- **С 1 июня 2026**: Для средств виртуализации и офисного ПО
- **С 1 января 2027**: Для облачных и серверных систем
- **С 1 июня 2027**: Для прикладного и отраслевого ПО
- **С 1 января 2028**: Для промышленного ПО

### Российские ОС для совместимости

| ОС | Описание |
|----|----------|
| **Astra Linux** | Самая популярная, особенно Special Edition для госсектора |
| **RED OS** | Server 7.3/8, сертифицированные редакции |
| **ALT Linux** | SP Server/Workstation 10/11 |
| **ROSA** | Enterprise/Chrome |
| **BaseALT** | Различные редакции |

### Требования к локализации

1. **Исходный код**: Разработка должна вестись в РФ или российскими специалистами
2. **Серверная инфраструктура**: На территории РФ
3. **Техподдержка**: Обязательно по всей территории России
4. **Документация**: На русском языке

## Трансграничные передачи

### Restrictions

**С 1 сентября 2015**: Запрет на передачу персональных данных граждан РФ за рубеж без соблюдения требований.

#### Страны-получатели (категории):

**"Безопасные страны" (адекватная защита)**:
- Страны Конвенции Совета Европы
- В "белом списке" Роскомнадзора: Австралия, Израиль, Канада, Япония, Южная Корея, Сингапур, Бразилия и др. (всего 29+ стран)
- Китай **НЕ** в списке

**"Небезопасные страны"**:
- Все остальные страны

### Для нашего сервиса

#### Сценарий 1: Метрики без персональных данных

Могут передаваться за рубеж свободно, если не содержат идентификаторов пользователей.

#### Сценарий 2: Логи с IP/Email

Требуют:
1. Предварительного уведомления Роскомнадзора
2. Хранения основной копии в РФ
3. Согласия пользователя (для небезопасных стран)

#### Требования к уведомлению (с 1 марта 2023):

**Шаг 1**: Сбор информации от иностранных получателей о:
- Мерах защиты данных
- Правовых требованиях в стране назначения
- Контактных данных получателей

**Шаг 2**: Подача уведомления в Роскомнадзор:
- Данные оператора
- Основание и цель трансграничной передачи
- Категории и список передаваемых ПД
- Список стран назначения
- Дата оценки безопасности иностранного получателя

**Шаг 3**: Ожидание:
- Для "безопасных стран": можно proceed через 10 рабочих дней, если нет возражений
- Для "небезопасных": требуется подтверждение (до 15 дней)

#### Исключения:

Допускается передача в небезопасные страны при:
- Письменном согласии субъекта
- Необходимости для выполнения договора
- Защиты жизни/здоровья
- Требований международных договоров РФ

## Data centers

### Требования к локации серверов

**Обязательно для SaaS с клиентами из РФ**:

1. **Физическое нахождение в РФ**: Все базы данных с ПД граждан РФ
2. **Региональное покрытие**: Рекомендовано размещение в нескольких регионах (Москва, Санкт-Петербург, Новосибирск, Екатеринбург) для latency < 6-10 мс
3. **Юрисдикция**: ЦОД должен находиться под юрисдикцией РФ

### Российские облачные провайдеры (2025)

| Провайдер | Особенности |
|-----------|-------------|
| **Yandex Cloud** | Крупнейший, 47,000+ клиентов, 3 собственных ЦОД (Москва, СПб, Новосибирск), рост выручки 46% в 2025 |
| **SberCloud** | 37 облачных сервисов, фокус на AI/ML, строят новые ЦОД (до 154 MW) |
| **Rostelecom Cloud** | Крупнейший телеком, множество ЦОД по всей стране |
| **Cloud.ru** | Former VK Cloud |
| **Selectel** | Частный провайдер, ЦОД в СПб и Москве |
| **2GIS** | Собственная инфраструктура |

### Зарубежные провайдеры в РФ

- **Major Western providers** (AWS, Azure, Google Cloud) существенно ограничили работу в РФ после 2022
- Для compliance 152-ФЗ необходимы локальные партнеры или собственная инфраструктура

### Requirements к инфраструктуре

| Параметр | Рекомендация |
|----------|--------------|
| **Локация** | Минимум 2 Availability Zone в разных регионах РФ |
| **Backup** | Обязательно хранение backup в РФ |
| **Encryption** | TLS 1.3 для transit, AES-256 для rest |
| **Logging** | Хранение логов безопасности минимум 3 года |
| **Access control** | Multi-factor authentication для admin доступа |

## Лицензии

### Нужны ли?

#### Для SaaS мониторинга:

**Не требуются**:
- Стандартный мониторинг инфраструктуры
- Метрики и алертинг
- Dashboards и отчетность

**Могут потребоваться**:
- **Сертификат ФСТЭК** — если система обрабатывает защищаемую информацию (госсектор, банковские данные)
- **Лицензия ФСБ** — для использования криптографии (если используется встроенная защита)

#### Сертификация ФСТЭК (если требуется):

| Уровень доверия | Применение |
|-----------------|-------------|
| Уровень 1-4 | Для государственных информационных систем (ГИС) |
| Уровень 4 | Высший уровень, для систем класса защиты 1Г |

#### Новые требования ФСТЭК (конец 2025):

Утверждена **"Методика анализа защищенности информационных систем"**:
- Тестирование систем с ИИ
- Контейнеризированные среды
- Промышленное оборудование

#### Рекомендации:

1. **Для B2B**: Начать без сертификации, добавить при необходимости
2. **Для госсектора**: Рассмотреть сертификацию после стабилизации продукта
3. **Self-hosted версия**: Клиент самостоятельно получает сертификат для своего развертывания

## Чек-лист compliance

### Запуск продукта:

**Юридические основы:**
- [ ] Разработать Политику обработки персональных данных (согласно 152-ФЗ)
- [ ] Разработать Согласие на обработку ПД (отдельный документ, с 1.09.2025)
- [ ] Разработать Пользовательское соглашение
- [ ] Зарегистрироваться в Роскомнадзоре как оператор ПД (если требуется)

**Инфраструктура:**
- [ ] Выбрать провайдера с ЦОД в РФ (Yandex Cloud, SberCloud, Selectel, Rostelecom)
- [ ] Настроить geo-replication внутри РФ
- [ ] Внедрить encryption at rest и in transit
- [ ] Настроить логирование безопасности

**Продукт:**
- [ ] Реализовать анонимизацию метрик на агенте
- [ ] Разделить хранение метрик и пользовательских данных
- [ ] Добавить возможность self-hosted развертывания
- [ ] Реализовать Data Retention Policy

**Документация:**
- [ ] Подготовить Privacy Policy на русском языке
- [ ] Описать процедуру обработки запросов пользователей (права на доступ, удаление, исправление)
- [ ] Описать процедуру уведомления об инцидентах

### Операция:

**Ежемесячно:**
- [ ] Отправлять уведомления в Роскомнадзор об изменениях (до 15 числа)
- [ ] Проводить аудит логов безопасности
- [ ] Обновлять документацию при изменениях процессов

**По требованию:**
- [ ] Обрабатывать запросы пользователей на доступ/удаление данных (в течение 10 дней)
- [ ] Уведомлять об утечках данных (24/72 часа)

**Ежегодно:**
- [ ] Пересматривать Политику обработки ПД
- [ ] Проводить风险评估 (risk assessment)
- [ ] Обучение сотрудников по информационной безопасности

**При трансграничной передаче:**
- [ ] Предварительно уведомить Роскомнадзор
- [ ] Получить согласие пользователя (если требуется)
- [ ] Убедиться в безопасности иностранного получателя
