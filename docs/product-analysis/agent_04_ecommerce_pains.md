## Критичные метрики для мониторинга

### 1. Uptime (Доступность)

| Уровень SLA | Допустимый даунтайм в месяц | Стоимость реализации |
|-------------|----------------------------|----------------------|
| **99.9%** (three nines) | ~43 минуты | Умеренная |
| **99.99%** (four nines) | ~4.3 минуты | Высокая |
| **99.999%** (five nines) | ~26 секунд | Очень высокая |

**Требования e-commerce:**
- Минимум 99.9% для малого/среднего бизнеса
- 99.99%+ для крупных маркетплейсов
- 99.999% для критических периодов (Black Friday, распродажи)

### 2. Response Time (Время отклика)

- **< 1 секунда**: оптимально для e-commerce
- **> 1 секунда**: потеря 80% пользователей
- **> 2 секунды**: 40% пользователей покидают сайт
- **> 3 секунды**: критическое падение конверсии

**Бенчмарки:**
- P50 (медиана): < 500ms
- P95: < 1.5s
- P99: < 3s

### 3. Error Rate (Уровень ошибок)

- Должен быть близок к 0% для транзакционных операций
- Критичные ошибки: 5xx responses
- Некритичные: 4xx (client errors)

### 4. Checkout Success Rate

- Метрика успеха завершения заказа
- Должна быть > 95%
- Мониторинг на каждом этапе checkout funnel

### 5. Payment Gateway Response Time

- Критично для завершения транзакций
- Target: < 2 секунды
- Мониторинг каждого платежного провайдера отдельно

### 6. Inventory Sync Status

- Актуальность остатков на складах
- Предотвращение overselling
- Мониторинг задержек синхронизации

### 7. CDN & Static Content Delivery

- Время загрузки изображений товаров
- CSS/JS delivery
- Impact на Core Web Vitals (LCP, CLS)

## Известные кейсы даунтаймов

### Shopify (Cyber Monday 2024)
- **Дата:** 1 декабря 2024
- **Длительность:** 5.5-6 часов
- **Причина:** Сбой в системе login verification
- **Влияние:**
  - 4,000+ одновременных жалоб
  - Акции упали на 6%
  - Миллионы потерянных транзакций
  - Отключены: admin, POS, checkout, inventory

### AWS (октябрь 2025)
- **Дата:** 20 октября 2025
- **Длительность:** ~15 часов
- **Причина:** Критический сбой инфраструктуры
- **Влияние:**
  - 1,000+ крупных предприятий затронуто
  - Прямые потери: $160M
  - Общие потери: до $10B
  - 120 fulfillment centers затронуто
  - 6M заказов задержано

### Amazon (исторические кейсы)
- **Март 2025:** 30-40 минут, ~$4.7M потерь
- **Март 2016:** 20 минут, $3.75M потерь ($187,500/мин)
- **2021:** 40 минут, $4.72M потерь

### Ozon / Wildberries (Россия)

**Ozon (сентябрь 2024):**
- **Проблема:** Исчезновение страниц товаров с фронтенда
- **Причина:** Системный баг платформы
- **Влияние:** Страницы товаров отображались только текстом, изображения не грузились

**Ozon / Wildberries (декабрь 2024):**
- **Проблема:** Массовый интернет-сбой в России
- **Причина:** Меры безопасности против дронов (официально)
- **Влияние:**
  - Недоступность в Москве, Свердловской, Иркутской областях
  - Падение заказов на 50% для кросс-бордер продавцов
  - Затронуты все операторы (Beeline, Megafon, MTS, Tele2)

### CrowdStrike (июль 2024)
- **Дата:** 19 июля 2024
- **Влияние:** 8.5M устройств crashed
- **Потери:** Десятки миллиардов долларов
- **Контекст:** Один из крупнейших сбоев в истории

## Боли e-commerce при мониторинге

### 1. Data Silos and Fragmentation
- Логи, метрики и трейсы разбросаны по разным системам
- 5+ дискретных monitoring платформ в 65% компаний
- Сложность cross-platform queries для диагностики

### 2. Высокие затраты на хранение
- Elasticsearch и традиционные инструменты очень дорогие
- Log-данные растут экспоненциально во время промо-акций
- Приходится сэмплировать данные, теряя insights
- Некоторые решения предлагают 140x lower storage costs

### 3. Сложность распределённых систем
- Один user request проходит через десятки микросервисов
- Терабайты логов ежедневно
- Миллионы точек метрик
- Тысячи correlation ID в минуту

### 4. Пробелы в real-time мониторинге
- Во время распродаж традиционные tools face performance bottlenecks
- Задержки в anomaly detection
- Пользователи жалуются раньше, чем срабатывают алерты

### 5. Проблемы с incident response
- Много алертов, но непонятно, влияет ли это на бизнес
- Опора на жалобы клиентов для подтверждения проблем
- Poor coordination during incidents
- Медленная fault isolation

### 6. Multi-channel integration issues
- Онлайн-заказы, офлайн POS, логистика не унифицированы
- Frontend performance, API response, DB monitoring не связаны
- Gap между UX и backend monitoring

### 7. IT vs Business perspective gap
- Традиционный мониторинг фокусируется на "IT availability", не "business continuity"
- При падении серверов сложно определить impact на бизнес
- Отсутствие business-centric monitoring

### 8. Cross-border e-commerce проблемы
- Множество third-party интеграций
- Любые задержки = финансовые потери
- Requirements misalignment, низкая communication efficiency

## Выводы для продукта

### Что критично для e-commerce в нашем продукте:

1. **Бизнес-ориентированные метрики** — не просто "server is up", а "checkout работает"
   - Мониторинг воронки заказов
   - Synthetic transactions для критичных user journeys

2. **Real-time alerting** — минуты имеют значение
   - MTTR (Mean Time To Recovery) должен быть минимальным
   - SRE team должна реагировать в минутах

3. **Cost-effective storage** — хранение всех данных без сэмплирования
   - 140x cheaper чем Elasticsearch
   - Полные логи для post-mortem анализа

4. **Unified observability** — единый стек
   - Logs + Metrics + Traces в одном месте
   - Correlation между frontend/backend issues

5. **SEO protection** — мониторинг доступности для поисковиков
   - 503 Service Unavailable при planned downtime
   - Мониторинг crawl errors

6. **SLA tracking** — прозрачная отчётность
   - Автоматический расчёт uptime SLA
   - Исторические отчёты для внутреннего анализа

7. **Peak load handling** — готовность к Black Friday
   - Масштабирование без потери observability
   - Performance benchmarking

8. **Integration monitoring** — third-party dependency tracking
   - Payment gateways
   - Delivery services
   - CDN providers
